# Production-домен getCareer

23 ноября 2026 подключён https://getcareer.app. В интерфейсе и заголовке вкладки
название пишется `getCareer`. Регистрация и DNS находятся в
Cloudflare; приложение, PostgreSQL и приватные файлы остаются на существующем
EC2 `i-030fa1abecd9da0ac` в eu-north-1. Данные повторно не переносились.

CloudFormation stack `qa-job-searcher-domain` закрепил Elastic IP `13.51.39.52`.
Он заменил прежний динамический IPv4, дополнительный постоянно занятый IPv4
не создавался. DNS A-записи apex, www и api указывают на него и проксируются
Cloudflare. Режим SSL/TLS — Full (strict), origin использует Caddy с управляемыми
публично доверенными сертификатами и автоматическим продлением. Сертификаты и
приватные ключи остаются на зашифрованном EBS, вне Git и CI.

AWS Security Group допускает 80/443 только из 15 официальных IPv4-диапазонов
Cloudflare, проверенных 23 ноября 2026: https://www.cloudflare.com/ips-v4/.
SSH, Docker API, порт приложения 8000 и PostgreSQL не открыты извне. 8000 связан
с loopback, управление сервером идёт через SSM. При изменении списка адресов
Cloudflare нужно обновить domain.json; открывать origin всем адресам не требуется.

Основной сайт использует same-origin `/api`. Cookies не расширены на поддомены,
CORS для внешних origins не включён. www перенаправляется на основной домен.
По подтверждённому выбору пользователя `api.getcareer.app` существует в DNS, но
возвращает 404 для всех путей и не проксирует запросы к приложению.

Снаружи доступны интерфейс/статические файлы, GET `/api/session`, POST `/api/login`,
обработчики принятия приглашения и восстановления по действительному одноразовому
токену. Последние сохраняют проверки Origin и срока/назначения токена. Публичный
session endpoint нужен для первоначального отображения входа и не выдаёт личные
данные без сессии. Все пользовательские API требуют серверную авторизацию,
изменения также CSRF, административные действия — права администратора.

Приложение отдаёт HTML с `Cache-Control: no-store, no-transform`, чтобы прокси
сохранял исходную страницу без вставки скрипта аналитики. CSP допускает скрипты
только с основного домена. Проверять ответ Cloudflare с заголовками браузера.
[Cloudflare Web Analytics](https://developers.cloudflare.com/web-analytics/get-started/)

Caddy закрывает `/health/*`, `/docs`, `/redoc`, `/openapi.json`, `/metrics`, `/debug`,
`/.env`, `/.git*` и начальный `/api/setup`. Swagger/OpenAPI дополнительно выключены
в приложении. Health остаётся доступным только внутри сервера для Docker/CD.
Проверка `ci/verify_public.py` прошла для 24 адресов: 200 у интерфейса/session,
401 у защищённых данных без сессии, 404 у служебных и всех проверенных api-путей.
Это конкретная проверка доступа, не гарантия отсутствия всех уязвимостей.

Первые проверки readiness после переноса корректно получили 503 при maintenance.
Отдельно выявлены обрывы тяжёлого Python health process по прежнему timeout 7s.
Production override сохраняет реальные проверки схемы БД/heartbeat, увеличивает
таймаут до 30s и интервал до 60s, чтобы сами проверки не расходовали CPU постоянно.
Это не выключение healthchecks и не переход на более дорогой EC2.

Все шесть служб получили healthy после проверки нового HTTPS.
Ngrok остановлен и отключён в systemd после этих проверок; прежний tunnel больше не используется.
Исходящий трафик Security Group ограничен TCP 80/443 для внешних источников,
AWS и обновлений; прежнее разрешение всех протоколов удалено. История прежнего переноса сохранена в aws-migration-status.md; её старые
адреса относятся к проверкам 21 ноября, текущий адрес указан в этом документе.
Автоматическая доставка описана в [cicd.md](cicd.md).
