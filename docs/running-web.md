# Запуск веб-приложения

## Установка

Нужны Python 3.12+ и Node 22. Установленные и проверенные Python-зависимости
закреплены в `requirements.lock`, JavaScript-зависимости — в `frontend/package-lock.json`.

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.lock
.venv/bin/python -m pip install --no-deps -e .
npm --prefix frontend ci
npm --prefix frontend run build
```

В отдельном терминале запустить API, в другом — worker:

```bash
PYTHONPATH=src WEB_PORT=8033 WEB_ORIGINS=http://127.0.0.1:8033,http://localhost:8033 .venv/bin/python -m qa_job_bot.web
PYTHONPATH=src .venv/bin/python -m qa_job_bot.worker
```

Открыть `http://127.0.0.1:8033`. Код первоначальной настройки находится в
`data/setup-token`, доступен только локально и удаляется после создания пароля.
Пароль от 12 символов вводит владелец. В базе сохраняется scrypt-хеш, сессии
действуют сутки; для мутаций обязательны origin и CSRF-токен. Исходные файлы,
профиль, диалоги и документы не отдаются через статический сервер.

Поиск выполняется worker при первом запуске, раз в 3 часа и по кнопке обновления.
Выдача повышает приорит Middle/Senior Manual QA и Full-stack QA; остальные
релевантные QA-роли сохраняются в выдаче при прохождении общих фильтров.
Адаптеры и фильтры используют существующие `config/*.toml`. Рабочая SQLite
мигрирует с резервной копией `data/jobs.sqlite3.pre-web.bak`: история доставок
Telegram сохраняется. Старые записи без описаний появляются в текущей выдаче
после повторного получения и фильтрации. Действия applied и архив хранятся отдельно.

Перед первым документом загрузить PDF/DOCX до 10 MiB, проверить извлечённые факты
и нажать сохранение эталона. Диалог с помощником расположен в профиле и в карточке
задания; новые сведения подтверждаются через форму. Активный эталон не меняется
до сохранения новой версии. CV всегда английский, письмо — на языке описания.
Если текста недостаточно для определения языка, письмо блокируется с пояснением.

DOCX переносит базовую типографику и поля. PDF сохраняется целиком; агент получает
изображения его страниц вместе с подтверждёнными фактами и параметрами оформления.
В профиле можно сравнить извлечённые абзацы с оригиналом, переключать страницы
и скачать исходный файл. Для старого PDF нажать «Перечитать PDF», проверить целые
абзацы и подтвердить новую версию. До этого остаётся активен прежний эталон;
генерация по старому PDF без визуального эталона блокируется с пояснением.

Рендерер воспроизводит поддерживаемые шрифты, размеры, цвета, выравнивание,
интервалы, заголовки и линии разделов. Отдельный агент проверяет итоговый PDF
для PDF- и DOCX-эталона; отрицательная или недоступная проверка закрывает скачивание обоих
форматов. Сложные колонки, сканы, фотографии и декоративные элементы не клонируются
автоматически; пиксельное совпадение не обещается. Подробности разбора —
в `pdf-template.md`, изоляции и реальных проверок — в `agent-runtime.md`.

В карточке вакансии показаны эвристический рейтинг, причины совпадения и время
последнего поиска. У готового документа есть просмотр PDF в браузере и раскрываемое
содержание с подтверждёнными фактами, на которые ссылаются абзацы. Просмотр доступен
только владельцу после полной проверки: PDF сверяется по хешу файла, текст — по
хешу утверждённого черновика.

## OpenAI API

Worker использует платный OpenAI Agents API с моделью `gpt-5.6-luna` и reasoning
`medium`. Подписка и лимиты Codex для документов не используются. Отдельный
API-проект должен иметь доступ к модели и действующий баланс/биллинг.

В приватной директории `WEB_DATA_DIR` (по умолчанию `data`) нужны два файла:

- `openai-api-key` — только API-ключ одной строкой, без комментариев;
- `openai-agent.json` — ID сохранённого агента и настройки:

```json
{
  "agent_id": "agent_REPLACE_WITH_SAVED_AGENT_ID",
  "model": "gpt-5.6-luna",
  "reasoning_effort": "medium",
  "project_id": "proj_REPLACE_WITH_PROJECT_ID"
}
```

Оба файла должны принадлежать пользователю worker и иметь права `0600`.
Символические ссылки, публичные права и слишком большие файлы отвергаются.
Они исключены из Git и не выдаются веб-сервером. Ключ нельзя отправлять в чат,
комментарии, логи или коммиты. Замена содержимого ключа применяется к следующему
запросу без перезапуска. Глобальный `OPENAI_API_KEY` намеренно не используется.

В кабинете OpenAI создать агент с выбранной моделью. Приложение закрепляет для
каждой сессии инструкции своей роли, JSON-схему, `tools: []`, отключённые subagents,
`environment: none` и пустой список vaults. MCP работает локально по stdio;
публичный MCP-порт или подключение к GitHub/Drive/Gmail агенту не требуются.
Ошибка API или проверки блокирует документ; fallback на Codex отсутствует.

API-сессии сохраняются в проекте OpenAI и доступны в его кабинете. Они содержат
переданные факты, изображения и ответы; локальная история также сохраняется.
Расход токенов API, если доступен, записывается в metadata успешного этапа.
`null` означает ещё неизвестный расход, а не ноль. Итоговые расходы и повторные
попытки сверять с Usage в кабинете OpenAI.

Очередь хранится в SQLite. Закрытие страницы не останавливает её. Задание получает
15-минутный lease, общий таймаут исполнения — 14 минут. После аварийного завершения
worker истёкшее исполнение помечается ошибкой; владелец может создать новое.
Поздний ответ не может завершить отменённую задачу. При `revise` допускаются максимум
две повторные генерации с новой независимой проверкой. История версий и готовые
артефакты сохраняются до явного удаления владельцем в карточке вакансии.

## Ngrok и автозапуск macOS

В этом аккаунте уже есть постоянный dev domain `baboon-arriving-visually.ngrok-free.app`.
Адрес не нужно резервировать повторно. Он работает, пока Mac включён, подключён
к сети и процессы запущены; ngrok сам по себе не превращает Mac в круглосуточный сервер.

Конфигурация автозапуска генерируется без включения токенов:

```bash
PYTHONPATH=src .venv/bin/python -m qa_job_bot.deployment --domain baboon-arriving-visually.ngrok-free.app
```

Три plist в `.runtime/launchd/` предназначены для `~/Library/LaunchAgents/`:
`com.qajobsearcher.web`, `com.qajobsearcher.worker`, `com.qajobsearcher.tunnel`.
Они задают каталог проекта, localhost:8033, точные разрешённые Origin, перезапуск
при сбое и приватные логи в `data/logs`. Ngrok использует существующую локальную
конфигурацию аккаунта; inspection отключён, чтобы не сохранять тела CV и диалогов
в инспекторе туннеля. Не запускать одновременно ручные и launchd-копии worker/API.

Для ручного туннеля добавить HTTPS-origin домена в `WEB_ORIGINS` и выполнить:

```bash
ngrok http 8033 --url=https://baboon-arriving-visually.ngrok-free.app --inspect=false
```

Остановить автозапуск можно командой `launchctl bootout gui/$(id -u)/com.qajobsearcher.web`
и аналогично для `worker`, `tunnel`. Для возврата использовать `launchctl bootstrap`
с доменом пользователя и соответствующим plist. Удалять данные для перезапуска не нужно.

Telegram запускается отдельно после указания числового user ID в
`TELEGRAM_ALLOWED_USER_IDS`. При пустом списке бот завершает запуск с ошибкой;
в текущей локальной конфигурации он оставлен остановленным по решению владельца.
Его polling не дублируется веб-сервисом; общий формат SQLite совместим. В этой реализации у Telegram
сохраняется прежнее расписание, а веб-поиск имеет собственную очередь.

## Проверки

```bash
PYTHONPATH=src .venv/bin/python -m qa_job_bot.quality
```

Команда выполняет Ruff, Python unit/integration/API-тесты с полным покрытием,
раздельный порог 90% строк и ветвлений, TypeScript-сборку, UI/component coverage
и Playwright E2E против настоящего API/SQLite/worker. E2E использует синтетический
профиль и контролируемую внешнюю модель, не расходуя аккаунт пользователя.
Требуется установленный Chromium: `cd frontend && npx playwright install chromium`.
В CI для E2E задаётся `QA_E2E_PYTHON=python`; локально используется `.venv/bin/python`.

Live-проверки OpenAI API/MCP и атак выполняются отдельно в доверенном окружении, их
результаты описаны в `agent-runtime.md`. Никогда не выдавать прохождение mocks
за доказательство реальной интеграции. Последний общий отчёт — `verification.md`.

## Восстановление истории Telegram

`history_import` читает локальную историю доставок начиная с выбранного времени,
получает полные описания из разрешённых публичных источников и повторяет текущий
matching. В Telegram не входит и статусы прочтения не меняет. Исходные страницы
проверяются с allowlist, DNS/IP-проверкой, ограничением размера и запретом редиректов.
HTTP 429 останавливает источник до следующего запуска; `Retry-After` сохраняется
в приватном отчёте. Повторный запуск допустим после указанной источником паузы.

```bash
PYTHONPATH=src .venv/bin/python -m qa_job_bot.history_import
```

Без `--apply` это только отчёт в `data/history-import-report.json`. Для продолжения
после ограничения и применения результатов:

```bash
PYTHONPATH=src .venv/bin/python -m qa_job_bot.history_import --resume data/history-import-report.json --apply
```

Восстановленные и проверенные записи кэшируются в отчёте. Дубликаты по внешнему ID
объединяются с текущей выдачей, история доставок и пользовательские состояния не
удаляются. Принятые записи сохраняются в `imported_jobs`, поэтому не исчезают из-за
ограниченного окна очередного поиска. Они доступны обычным кнопкам applied/архива.
Недоступность страницы не считается доказательством закрытия; явная архивность
источника отдельно отмечается как причина отклонения.
