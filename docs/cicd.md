# CI/CD GetCareer

23 ноября 2026. Целевое приложение находится в `multiuser/`, production URL —
https://getcareer.app. Сохранённая SQLite-версия в корне проверяется отдельно.

## Обязательные проверки

Единый workflow `CI` вызывает оба полных quality gate и Docker-репетицию
многопользовательского runtime. Gate блокируется при любой неуспешной обязательной
проверке. Backend и frontend каждой версии сохраняют независимые пороги 90%
исполняемых строк и 90% ветвлений по всему собственному исходному коду.
JUnit, Vitest JSON и Playwright JSON дополнительно проверяются: ноль failed,
errors, skipped, todo и flaky, ненулевое число проходящих тестов. Повторные
попытки Playwright выключены. Неисполненные сценарии не считаются успешными.

Ruff проверяет Python lint/формат; ESLint проверяет TypeScript/React. Radon
публикует сложность функций и maintainability index. Историческая сложность не
скрывается исключениями, но её отчёт не является числовым merge gate. Названия
и архитектурный смысл дополнительно проверяются при PR review; ни один из этих
инструментов не доказывает человекочитаемость автоматически.

CodeQL `security-and-quality` анализирует Python, JavaScript/TypeScript и Actions;
HIGH/CRITICAL findings блокируют gate. Bandit блокирует новые замечания средней
и высокой тяжести с высокой уверенностью. Единственное явно разобранное B310
относится к health URL из доверенного серверного окружения: код проверки не
получает пользовательского URL и не раскрывает ответ. Исключение привязано к
пути, rule ID и хешу точного кода, действует до 1 февраля 2027; изменения или
истечение срока снова блокируют gate. Это не общее отключение правила.

`pip-audit` проверяет три Python lock-набора, `npm audit` — три frontend/CI набора
и блокирует moderate и выше. Gitleaks проверяет Git-историю. Trivy проверяет IaC
и готовый ARM64 image, блокируя HIGH/CRITICAL. Неисправимые замечания не скрываются
флагом ignore-unfixed.
Для IaC два решения перечислены в `ci/trivy-reviewed.yaml` с точными путями и
сроком до 1 февраля 2027: исходящие TCP 80/443 к динамическим внешним адресам
и SSE-S3 вместо платного customer-managed KMS key. Входящие правила этим не
расширяются; остальной исходящий трафик запрещён. Уведомления CVE не исключаются.
Формат scoped/expiring decisions описан в [документации Trivy](https://trivy.dev/docs/latest/guide/configuration/filtering/). Actions закреплены по полным commit SHA; CI-зависимости
закреплены с хешами. Dependabot alerts и secret-scanning push protection включены.
Отчёты содержат только код и синтетические тестовые данные, срок хранения 7 дней.

## 99% стабильности

Пользователь подтвердил: 100% обязательных тестов в каждом прогоне, отдельно
целевая стабильность CI >=99%. Workflow `CI reliability` считает последние
100 завершённых push-прогонов `CI` в `master`. Успех только с первой попытки;
rerun, failure и cancellation уменьшают показатель. При результате ниже 99%
проверка reliability завершается ошибкой. Пустая или малая выборка не является
доказательством будущей стабильности. Reliability не блокирует исправляющий CD:
блокировка по прошлым сбоям могла бы запретить доставить сам фикс.

## Доставка

Production запускается только из `master` и после `CI gate`. Ветки/PR не имеют
доступа к production environment. Сборка выполняется на GitHub-hosted ARM64,
на сервер передаётся готовый образ, Compose и Caddyfile. Тестовые/сборочные
задания не получают AWS-ключей, OpenAI-ключей, рабочих БД или исходных CV.

OIDC role `qa-job-searcher-github-deploy` доверяет только environment production
репозитория BadKirill/qa-job-searcher. GitHub environment разрешает только master.
Роль может записывать только `artifacts/releases/*` в приватный S3 и запускать
только `qa-job-searcher-deploy` на `i-030fa1abecd9da0ac`; IAM, произвольный shell,
чтение backups и пользовательских credentials ей не предоставлены.
`GetCommandInvocation` имеет resource `*`, потому что операция не поддерживает
ограничение на ARN отдельной команды. Долгоживущих AWS или SSH-ключей в GitHub нет.

Установленный root helper проверяет SHA-256 manifest и каждого payload, source
revision label, ARM64 и конфигурацию Caddy, затем берёт общий lock с backup.
Перед изменением выполняется согласованная offsite-копия. Приложение закрывает
запись, задания завершаются, писатели останавливаются; заменяются конфигурация и
image, проходят миграции и реальные healthchecks. Maintenance выключается перед
проверкой readiness: в режиме обслуживания readiness намеренно возвращает 503.
Проверка всех служб и внешняя матрица 200/401/404 обязательны для успешного CD.

При ошибке прежний image/config возвращаются только если revision БД не изменилась.
При смене схемы остаются maintenance и остановленные писатели: автоматическое
восстановление старой БД могло бы уничтожить новые данные. Нужна проверка оператором.
Если ожидание SSM завершилось timeout, сначала проверяют уже отправленную команду;
новый платный/изменяющий запуск автоматически не отправляется.

Исходники инфраструктуры: `infra/aws/cicd.json`, `domain.json`, Caddyfile и
Compose override. Старый ручной workflow Deploy VPS удалён: он относился к другой
версии и мог обходить новые gates. Удаление workflow не удаляет сохранённые данные.

Actionlint, Ruff и ESLint прошли. После обновлений npm audit и pip-audit не находят

секретов в проверенной Git-истории. CodeQL Python/JS/Actions и Trivy IaC прошли на GitHub.

Финальный CI, ARM64 image scan и первая автоматическая доставка требуют успешных
завершённых runs. Актуальные результаты публикуются в [Actions](https://github.com/BadKirill/qa-job-searcher/actions/workflows/ci.yml)
и [production deployments](https://github.com/BadKirill/qa-job-searcher/deployments).
Наличие YAML само по себе не означает рабочий CI/CD. Контролируемые внешние ответы
в regression gate не доказывают доступность живого OpenAI API/MCP; production
credentials и личные документы не передаются в GitHub Actions.
