# Политика качества и тестирования

Статус: обязательные требования к первой реализации. Coverage, UI и E2E-инструменты
установлены; фактические результаты и ограничения фиксируются в `verification.md`.
Полный gate запускается через `python -m qa_job_bot.quality`.

## Измеримые пороги

| Область | Строки | Ветвления | Правило |
| --- | --- | --- | --- |
| Собственный Python backend, worker, MCP, политика безопасности | >= 90% | >= 90% | Два отдельных порога |
| Собственный TypeScript/React frontend | >= 90% | >= 90% | Два отдельных порога |
| Критические пользовательские сценарии | Все перечисленные | Все обязательные исходы | E2E-матрица, а не процент строк |

Backend и frontend не усреднять. Общий процент lines+branches также не заменяет
отдельные пороги. Использовать неокруглённые отношения covered/total; например,
89.99% не проходит. Область без исполняемого кода не является доказательством 100%.

Покрытие — объединение результатов применимых тестов над одной и той же сборкой.
Не требовать, чтобы каждый уровень тестов отдельно повторно покрывал 90% всего кода.
При этом наличие всех пяти уровней и прохождение их обязательных сценариев проверяется
отдельно. Повторные прогоны одного теста процент не увеличивают.

В знаменатель входят неисполненные собственные файлы, entry points, обработка ошибок,
планировщик, миграции, адаптеры, MCP, авторизация и защитные проверки. Исключаются только
сторонние зависимости, сгенерированные внешними инструментами файлы, сборочные артефакты,
тесты, данные и декларации типов без исполняемого кода. Собственный код не помечать
`no cover`, `istanbul ignore` или подобными директивами для достижения порога.

## Инструменты первой реализации

- Python: pytest, pytest-asyncio, pytest-cov/coverage.py с branch coverage;
  JSON/XML/HTML-отчёты. Проверять строки и ветвления раздельным quality gate.
- Frontend: Vitest + React Testing Library + user-event и coverage provider;
  include всех исходных файлов, thresholds для lines и branches по 90%.
- Integration/API: реальный FastAPI, worker и временная SQLite; HTTP-контракты,
  реальные транзакции/миграции, управляемые имитации внешних источников.
- MCP: настоящий клиент/серверный транспорт, инициализация, tools/list, tools/call,
  схемы, авторизация и ограничение контекста задачи.
- E2E: Playwright против собранного frontend, API, worker и временной базы.
  Воспроизводимые внешние ответы в PR CI; отдельный реальный smoke test Codex/MCP
  перед первой публикацией и при изменении интеграционного пути.

В CI не пересылать персональный CV провайдерам. Использовать синтетический профиль
и тестовый шаблон. Реальный smoke test запускать в доверенном окружении с отдельными
секретами; публичный PR не получает доступ к секретам или self-hosted runner владельца.
Отсутствие доступа к модели отражать как незавершённую проверку, а не как успех.

## Обязательные уровни

| Уровень | Что проверяет |
| --- | --- |
| Unit | matching, нормализацию, разбор, пагинацию, переходы состояний, факты и policy-функции |
| UI/component | Карточки, формы, доступность с клавиатуры, loading/error/empty, кнопки и подтверждения |
| Integration | SQLite/миграции, очередь/lease, worker, рендерер, агентский адаптер и MCP |
| API | Валидацию, HTTP-коды, доступ, идемпотентность, пагинацию, SSE и скачивание |
| E2E | Полный путь пользователя через браузер и реальный backend до сохранённого результата |

## Матрица сценариев

Для каждой строки реализовать позитивные, негативные и краевые проверки на подходящих
уровнях. E2E обязательно покрывает основной путь и указанные критические отказы.

| Функция | Позитивный сценарий | Негативный сценарий | Краевые случаи |
| --- | --- | --- | --- |
| Поиск и matching | Middle+/допустимая география | Junior, чужая страна, запрет в конце описания | Нет seniority, смешанный Junior/Middle, Unicode, длинное описание |
| Источники | Частичный и полный сбор | Timeout, 429, 500, повреждённый ответ | Пустой фид, дубли, изменение карточки, ограниченное окно источника |
| Пагинация | Переходы по страницам | Невалидные page/page_size/snapshot | 0, 1, 9, 10, 11, 20, 21 вакансий; удаление последней карточки; новая выдача во время просмотра |
| Карточка | Все подтверждённые поля | Неверные/неподтверждённые поля | Все опциональные поля пусты, длинный заголовок, несколько языков/QA-меток, зарплата без периода |
| Applied и архив | Отметка, архив, возврат, отмена | Ошибка сохранения и откат UI | Двойной клик, две вкладки, обновление источника и перезапуск после изменения |
| Вход и доступ | Владелец получает свои данные | Нет сессии, истёкшая сессия, CSRF, чужой artifact/task ID | Выход при активном SSE, повторный вход, API/MCP без контекста владельца |
| Задать шаблон | Загрузка, диалог, подтверждение и активация | Неподдерживаемый/повреждённый файл, отмена | Размер/страницы ровно на лимите и +1, пустой файл, повторная отправка |
| Изменить шаблон | Новая версия атомарно заменяет активную | Ошибка разбора/проверки оставляет предыдущую | Две вкладки меняют версию, файл тот же, задача со старой версией ещё выполняется |
| PDF-эталон | Целые абзацы/bullets, исходные страницы, роли и оформление | Скан, несколько колонок, неизвестные glyph, активное содержимое, повреждённые PNG | Перенос пункта, WinAnsi bullet, разреженная страница, лимиты исходных/выходных пикселей |
| Повторное чтение PDF | Новый черновик, сохранённые оригинал и активная версия | Подмена исходного хеша, path traversal, доступ без сессии/CSRF | Старый эталон без reference, явный body, очистка инструкций, подтверждение новой версии |
| Визуальная проверка | Исходный и итоговый PDF видны отдельному reviewer, hashes совпадают | Несоответствие оформления, инструкция внутри картинки, невалидный ответ/timeout | Отмена и поздний ответ, подмена файла во время проверки, несовпадение любой привязки |
| Диалог в вебе | Уточнение и сохранение истории | Ошибка агента, попытка обойти подтверждение фактов | Повтор запроса, обрыв SSE, перезагрузка страницы, пустое/слишком длинное сообщение |
| Очередь | Генерация обоих документов | Ошибка/лимит модели, timeout, повреждённый ответ | Повторный клик, рестарт worker, истёкший lease, отмена и поздний ответ |
| Проверяющий агент | Все утверждения подтверждены | Выдуманный опыт, неверная цитата, отказ/timeout проверяющего | Противоречивые даты, похожие компании, нет исходного факта, исчерпаны исправления |
| Скачивание | Проверенный PDF/DOCX | Непроверенный/заблокированный файл, path traversal | Частичная запись, изменённый хеш, старый артефакт после новой версии |
| MCP | Разрешённый вызов для своей задачи | Лишний инструмент, чужая задача, невалидные аргументы | Повтор вызова, истёкшее разрешение, слишком большой ответ, разрыв транспорта |
| Миграция | Записи/доставки/статусы сохранены | Неполная миграция, rollback/восстановление | Пустая и старая базы, повтор миграции, занятая SQLite |

Набор атак из `agent-safety.md` — обязательная часть unit/API/integration и
критических E2E. Отдельно проверить путь «заблокированный результат нельзя скачать
по прямому API URL», даже если интерфейс скрывает кнопку.

PDF E2E проходит путь загрузки, просмотра страниц и источников, редактирования,
активации, повторного разбора с сохранением активного эталона, генерации и скачивания.
Отдельный критический исход — отказ визуального reviewer с запретом скачивания.
Реальный smoke использует синтетический PDF: случайный код только в растре доказывает
передачу изображения модели, а отдельные положительный/отрицательный прогоны проверяют
визуальную проверку. Этот smoke не заменяется ответами FixtureGateway в E2E.

## Проверка AI-поведения

Code coverage не измеряет отсутствие галлюцинаций. Нужен отдельный версионированный
набор синтетических вакансий, фактов, правильных документов и атак с ожидаемым
решением: allow, block или needs_input. Включить доброкачественные документы с
цитатами команд, чтобы не заблокировать любое техническое описание.

Обязательные safety-fixtures должны проходить полностью. Помимо стабильных проверок
политик с контролируемыми ответами, запускать реальные evals генератора и проверяющего
для релиза; сохранять версию модели/инструкций и результаты. Не скрывать неудачи
повторными прогонами до первого успеха и не называть конечный набор доказательством
защиты от любых будущих атак.

## Локальный gate и GitHub CI

Первая реализация добавляет одну документированную команду полного quality gate:
линтеры/типы, все пять уровней тестов, отдельные пороги покрытия и проверки безопасности.
Провал любого обязательного этапа делает результат неуспешным. Отчёты относятся
к проверяемому commit/build, включают покрытие, тесты и диагностические артефакты.

CI-конфигурацию подготовить локально, затем запустить на GitHub после первой реализации.
Перед первым push выполнить полный локальный gate и реальный интеграционный smoke test.
После появления репозитория сделать проверки обязательными для merge, если выбранный
тариф и права поддерживают эту настройку. Секреты, данные кандидата и сырые агентские
диалоги не публиковать в отчётах; публичные трассы Playwright использовать только
с синтетическими данными.
