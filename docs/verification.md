Дата: 4 октября 2026, Europe/Podgorica.

Полный локальный gate `python -m qa_job_bot.quality` завершился с кодом 0.
Ruff и production TypeScript/Vite build прошли. Проверялась одна итоговая версия
всего собственного исходного кода, включая не импортированные файлы и entry points.

| Проверка | Результат |
| --- | --- |
| Python unit/integration/API/MCP | 473 passed |
| Frontend unit/UI/API adapter | 41 passed |
| Browser E2E с реальным API/SQLite/worker/renderer | 6 passed |

| Backend ветвления | 774 / 786 = 98,4733% |
| Frontend строки | 332 / 335 = 99,1045% |
| Frontend ветвления | 329 / 341 = 96,4809% |

Строки и ветвления проверены отдельными порогами >=90%, без округления при решении
о прохождении. Нет skip/xfail обязательных тестов. Есть два предупреждения сторонних
библиотек: Starlette об адаптере httpx и pypdf о методе создания JS в негативном тесте.
Они не означают пропуска проверок. Browser E2E запускались без повторов при ошибке.

E2E покрывают вход, запрет внешнего доступа без сессии/CSRF, страницы 10+10+1,
исчезновение последней карточки страницы, applied/архив/возврат/перезагрузку,
загрузку и повреждённый шаблон, подтверждение фактов, сохранение диалога,
конфликт версий из двух вкладок, CV/письмо и PDF/DOCX, отказы модели/проверяющего,
отмену с поздним ответом, мобильный экран и выход. Остальные негативные и краевые
проверки распределены по unit/API/integration согласно testing-policy.md.

Отчёты: `coverage.json`, `coverage.xml`, `frontend/coverage/`,
`frontend/playwright-report/`, `frontend/test-results/`. Они исключены из Git;
CI сохраняет синтетические диагностические артефакты отдельно.

## Реальная интеграция

Локальный Codex с входом ChatGPT и настоящий MCP stdio успешно создали синтетический
английский CV. Отдельный reviewer вернул pass, совпадающий хеш и подтверждённые ID.
Реальные атаки в тексте вакансии не привели к передаче canary; выдуманные опыт,
сертификат и работодатель в черновике получили revise. История отладки и границы
проверки приведены в `agent-runtime.md`; это конечный набор проверок, не гарантия
отсутствия любых будущих галлюцинаций.

PDF и DOCX с английским и русским текстом прошли визуальную проверку. Выходной текст
обоих форматов сверяется программно с одобренным структурированным документом.

## Работающий сервис

API слушает только loopback:8033. API, worker и ngrok работают через macOS launchd
с перезапуском при сбое. Постоянный HTTPS-domain настроен; inspection ngrok выключен.
Проверены внешние запросы без сессии: session сообщает authenticated=false,
вакансии и документы возвращают 401. Владелец завершил первоначальную настройку;
setup-token удалён. Файлы и база не публикуются статическим сервером.

Свежий поиск восстановил 27 подходящих вакансий без ошибок источников. Импорт
истории Telegram выполняется отдельно, с повторным получением и фильтрацией;
результат будет добавлен после завершения.

## Ограничения

- Доступность зависит от включённого Mac, сети и лимита Codex.
- DOCX-шаблон передаёт базовую типографику/геометрию; сложный дизайн не копируется.
  PDF-шаблон используется как источник текста. Личный эталон ещё требует проверки
  после загрузки владельцем.
- E2E используют контролируемые ответы модели; реальный Codex/MCP проверен отдельно.
- Telegram Bot API не сообщает границу непрочитанного владельца. Импорт опирается
  на указанную владельцем первую вакансию и сохранённую историю отправок.
- Старый Telegram-контейнер сохраняет прежний polling и расписание. Веб-worker
  работает с общей совместимой базой, имея самостоятельную очередь.
