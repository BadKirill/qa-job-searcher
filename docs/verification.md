Дата итоговой локальной проверки: 8 октября 2026, Europe/Belgrade.

Полный локальный gate `python -m qa_job_bot.quality` завершился с кодом 0.
Ruff и production TypeScript/Vite build прошли. Проверялась одна итоговая версия
всего собственного исходного кода, включая не импортированные файлы и entry points.

Первая публикация находилась в приватном `BadKirill/qa-job-searcher`. GitHub Actions
успешно проверил исходную публикацию `71af845` на Ubuntu/Python 3.12/Node 22:
[Quality run](https://github.com/BadKirill/qa-job-searcher/actions/runs/37219219515).
Результаты ниже относятся к версии с OpenAI Agents API / GPT-5.6 Luna,
визуальным PDF-эталоном и независимыми проверками фактов и оформления.

CI запускается на push и pull request. Первоначальный запрос обязательного
`quality` для защищённой ветки был отклонён GitHub с HTTP 403: тариф не
поддерживал branch protection приватного репозитория. 7 ноября 2026 года
владелец разрешил сделать репозиторий публичным. После смены видимости создано
правило для `master`: изменения проходят через PR, `quality` от GitHub Actions
обязателен, ветка PR должна быть актуальна; обход для администратора отключён.

обращение, абзацы и подпись больше не перекрываются и имеют раздельные интервалы.

Проверка 9 октября покрывает подтверждённое удаление завершённых и сломанных
CV/cover letter: карточка исчезает, зарегистрированные и незарегистрированные

активной генерации, поискового задания и каталога-симлинка; UI сохраняет документ
при отмене подтверждения и показывает ошибку неуспешного удаления.

PDF E2E дополнительно проверяет целые абзацы и bullets, авторизованные исходный
файл и PNG, редактирование с сохранением роли и источника, активацию и повторный
разбор без изменения активной версии. Пройдены генерация с visual pass и скачиванием
обоих форматов, а также visual revise с запретом скачивания напрямую.

Отчёты: `coverage.json`, `coverage.xml`, `frontend/coverage/`,
`frontend/playwright-report/`, `frontend/test-results/`. Они исключены из Git;

## Реальная интеграция OpenAI API

Проверены настоящий API-ключ проекта владельца, сохранённый агент, модель
`gpt-5.6-luna`, reasoning `medium` и отдельные сессии без окружения и инструментов.
Синтетический CV прошёл генерацию, factual review, рендер и visual review.
Два raster-only кода из разных PDF прочитаны правильно. Выдуманные сертификат,
роль и работодатель в черновике получили revise; инструкция в вакансии не добавила
ложные факты. Поддельная команда в изображении PDF получила revise и запрет скачивания.
Все входы этих smoke/evals искусственные; личный CV владельца не использовался.

Короткий connection smoke вернул usage 6762 input / 18 output tokens. У дальнейших
немедленных ответов usage был null; это не нулевой расход. Детали API и исторические
проверки старого Codex-транспорта сохранены в `agent-runtime.md`.

Первый запуск quality gate дал 733 Python и 58 UI pass, но три browser E2E
завершились таймаутами при аномально длительном прогоне около двух часов. Повторный
полный gate с предотвращением сна на время процесса завершился с кодом 0;
все 7 E2E прошли за 29,6 секунды без retries. Пороги и таймауты не снижались.

Отдельный ранний negative smoke с неподтверждённым числом был заблокирован
программной проверкой до обработки семантического verdict. Он не засчитывается
как успешный semantic eval; отдельный сценарий без новых чисел дал revise.
Эти проверки не являются гарантией отсутствия всех галлюцинаций и prompt injection.

Входы и ожидаемые исходы закреплены в `tests/fixtures/document-tailoring.json`.
Сырые результаты API и PDF лежат вне репозитория. Эти конечные evals не доказывают

В предварительных прогонах обнаружены и сохранены как неуспехи: PDF A4 с дробными
размерами давал превью высотой 1401 вместо разрешённых 1400 px; reviewer ошибся при

отклонил. Исправлены округление preview и ограничение хешей в API JSON-схеме;
повтор имени остаётся закрытым отказом с ограниченным исправлением worker.
После исправлений приведённый выше реальный набор завершён. Mock E2E не используется
как доказательство этих API результатов.

На реальном профиле новый CV прошёл factual/assessment/visual проверки. Первая
генерация письма была заблокирована после ограниченных исправлений: модель связала
отдельные навыки с неподтверждёнными задачами и расширила «ревью автоматизированных
тестов» до общего ревью. Файл не выдавался. После этого цикл доработки дополнен
передачей предыдущего черновика вместе с замечаниями; правило отдельно разъясняет,
что список навыков не доказывает их применение. Синтетический real-API eval с этими
двумя дефектами получил исправленный черновик и полный assessment `pass`.
Повторный полный quality gate: те же 778/62/8 проходящих тестов и указанные выше
обновлённые значения покрытия. Проверки фактов и лимит исправлений не ослаблялись.

После исправления цикла доработки новое письмо для исходной вакансии также получило
factual/assessment/visual pass. Итоговый CV (две страницы) и письмо (одна страница)
визуально просмотрены, SHA-256 PDF/DOCX сверены с зарегистрированными артефактами.
Оба задания находятся в ready в работающем приложении; старая заблокированная
попытка сохраняется без доступных для скачивания файлов.

## Центрирование подзаголовка CV — 10 октября 2026

В двух последних готовых CV профессиональный подзаголовок получил стиль Normal
с выравниванием влево, хотя имя и контакты были центрированы. Рендерер теперь
рассматривает начальные безымянные разделы CV как шапку: ошибочный paragraph kind
и индивидуальные left/right overrides не меняют её центрирование. Инструкции
генератора и визуального reviewer явно включают подзаголовок и его переносы.

Полный локальный quality gate прошёл на текущем рабочем дереве:

- 784 backend unit/API/integration tests; строки 3532/3545 = 99,633286%,
  ветвления 1095/1112 = 98,471223%;
- 64 frontend unit/component tests; строки 431/434 = 99,308756%,
  ветвления 418/437 = 95,652174%;
- TypeScript/Vite production build, Ruff и 8 browser E2E прошли без retries;
- `git diff --check` прошёл.

Шесть регрессионных вариантов проверяют отсутствующий kind, body, role, contact,
bullet и entry, left/right overrides, несколько fact IDs, переносы и асимметричные
поля. Проверяются DOCX-стили и фактические координаты строк PDF; обычный текст,
должности после шапки и тело письма сохраняют своё выравнивание. E2E скачивает
оба формата через веб-интерфейс и проверяет центрирование их содержимого.
Тест сохранения геометрии эталона обновлён: вертикальные координаты сохраняются,
а имя и подзаголовок следуют новому требованию о центрировании.

Точный одобренный черновик проблемного CV прочитан из прежней API-сессии,
его хеш совпал с сохранённой проверкой. Повторный локальный рендер сохранил
текст и две страницы; разница центров четырёх строк шапки меньше 0,001 pt.
Обе страницы просмотрены визуально. Старые зарегистрированные файлы не изменены;
промежуточный результат и персональные данные находятся только в игнорируемой `data/`.

Реальный `gpt-5.6-luna` в двух отдельных visual-review сессиях отклонил исходный
PDF (`revise` с точным замечанием о смещённом подзаголовке) и принял исправленный
(`pass`, без замечаний). Привязки к хешам PDF, эталона и черновика проверены кодом.
Это проверка конкретной регрессии, а не гарантия отсутствия любых будущих ошибок модели.
Worker перезапущен при пустой очереди; локальный и публичный `/api/session`
после обновления вернули HTTP 200 с сохранённым рабочим пространством.
