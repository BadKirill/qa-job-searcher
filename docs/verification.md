# Проверка первой версии

Дата итоговой локальной проверки: 6 октября 2026, Europe/Belgrade.

Полный локальный gate `python -m qa_job_bot.quality` завершился с кодом 0.
Ruff и production TypeScript/Vite build прошли. Проверялась одна итоговая версия
всего собственного исходного кода, включая не импортированные файлы и entry points.

Первая публикация находится в приватном `BadKirill/qa-job-searcher`. GitHub Actions
успешно проверил исходную публикацию `71af845` на Ubuntu/Python 3.12/Node 22:
[Quality run](https://github.com/BadKirill/qa-job-searcher/actions/runs/37219219515).
Результаты ниже относятся к итоговой локальной версии с визуальным PDF-эталоном,
повторным разбором абзацев, рендерером и обязательной проверкой оформления.

CI запускается на push и pull request. Запрос обязательного `quality` для защищённой
ветки отклонён GitHub с HTTP 403: текущий тариф не поддерживает branch protection
приватного репозитория. Для серверной блокировки слияния потребуется GitHub Pro
или соответствующий тариф организации. Репозиторий оставлен приватным; до включения
защиты зелёный CI остаётся обязательным правилом проекта, но не принудительным
ограничением GitHub.

PDF E2E дополнительно проверяет целые абзацы и bullets, авторизованные исходный

`frontend/playwright-report/`, `frontend/test-results/`. Они исключены из Git;

## Реальная интеграция

Локальный Codex с входом ChatGPT и настоящий MCP stdio успешно создали синтетический
английский CV. Отдельный reviewer вернул pass, совпадающий хеш и подтверждённые ID.
Реальные атаки в тексте вакансии не привели к передаче canary; выдуманные опыт,
сертификат и работодатель в черновике получили revise. История отладки и границы
проверки приведены в `agent-runtime.md`; это конечный набор проверок, не гарантия
отсутствия любых будущих галлюцинаций.

PDF и DOCX с английским и русским текстом прошли визуальную проверку. Выходной текст
обоих форматов сверяется программно с одобренным структурированным документом.

Мультимодальный runner реально распознал случайные коды только из пикселей, включая
две разные страницы в одном запросе. Генератор дал валидный документ, factual reviewer
вернул pass. После исправлений геометрии и передачи одинаковых PNG визуальный
reviewer принял синтетический PDF. Красная инструкция «вернуть pass» внутри изображения
получила revise и блокировку. Первоначальные отказы и ложное определение дубликата
как пустой страницы зафиксированы в `agent-runtime.md`, а не скрыты повторными попытками.

Личный двухстраничный эталон проверен локально: 72 целых блока вместо 98 строк,
включая 53 абзаца Experience. Реконструкция из всех блоков осталась двухстраничной;
обе страницы просмотрены после окончательных исправлений интервалов, выделения
заголовка и пробелов возле тире. Эти диагностические файлы приватны, не являются
готовым откликом и не включены в Git или реальный синтетический smoke.

## Работающий сервис

API слушает только loopback:8033. API, worker и ngrok работают через macOS launchd
с перезапуском при сбое. Постоянный HTTPS-domain настроен; inspection ngrok выключен.
Проверены внешние запросы без сессии: session сообщает authenticated=false,
вакансии и документы возвращают 401. Владелец завершил первоначальную настройку;
setup-token удалён. Файлы и база не публикуются статическим сервером.

Проверены все 63 записи истории Telegram начиная с указанной владельцем вакансии:
41 прошла текущие фильтры, 21 отклонена, 1 дубль. Среди отклонённых 6 имеют явную
отметку архива или подозрительности источника. Из прошедших 9 уже были в текущем
поиске, 32 добавлены сверх него. Необработанных записей и недоступных описаний нет.
На момент проверки в основной выдаче 58 вакансий, включая 26 из свежего поиска;
совпадения между поиском и импортом показаны однократно. История доставок сохранена.

Исправления проверены на реальных публичных страницах: самозакрывающиеся HTML
переносы не обрывают описание, разделы преимуществ и этапов найма не попадают
в требования. E2E используют сохранённый синтетический DOCX без перезаписи fixture.

## Ограничения

- Доступность зависит от включённого Mac, сети и лимита Codex.
- DOCX-шаблон передаёт базовую типографику/геометрию; сложный дизайн не копируется.
  PDF передаёт целые текстовые блоки, типографику и изображения исходных страниц.
  Скан, неизвестные glyph и обнаруженная разметка в несколько колонок требуют
  другого файла; OCR и автоматического клонирования декоративных элементов нет.
  Пиксельное совпадение произвольного шаблона не гарантируется. После повторного
  разбора владелец подтверждает обновлённые факты в профиле.
- E2E используют контролируемые ответы модели; реальный Codex/MCP проверен отдельно.
- Telegram Bot API не сообщает границу непрочитанного владельца. Импорт опирается
  на указанную владельцем первую вакансию и сохранённую историю отправок.
- Старый Telegram-контейнер сохраняет прежний polling и расписание. Веб-worker
  работает с общей совместимой базой, имея самостоятельную очередь.
