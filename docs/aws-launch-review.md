# План переноса текущей установки в AWS

Подготовлено 21 ноября 2026, Europe/Belgrade. Ниже сохранён первоначальный review
перед запуском. После подтверждения пользователя инфраструктура создана в зоне
`eu-north-1b`; актуальные ресурсы и ограничения находятся в
[итоговом отчёте переноса](aws-migration-status.md). Перенос рабочих данных и публичного адреса завершён; ниже сохранена история подготовки.

Пользователь выбрал минимальную стоимость, перенос существующих данных и файлов
и подробные пояснения. Используются профиль `qa-job-searcher`, selected Region
`eu-north-1`, действующая многопользовательская версия из `.runtime/multiuser-stage10/`.
Старые исходники корня проекта не подменяют установленный release.

## Сервер и сеть

- Один `t4g.small`, ARM64, 2 vCPU и 2 GiB RAM, с 2 GiB swap.
- Официальная Ubuntu Server 24.04 LTS от Canonical, AMI `ami-09aa4a5ab990926c8`,
  сборка `20261120`; образ приложения также ARM64.
- Existing VPC `vpc-08f019956933548db`, публичная subnet
  `subnet-0422bf192bfef4352`, Availability Zone `eu-north-1a`.
- Входящих правил Security Group нет. PostgreSQL и API доступны только внутри
  Docker-сети и через loopback соответственно. SSH-ключ не создаётся.
- Управление через Systems Manager. Для выхода в интернет назначается один
  public IPv4; Elastic IP, NAT Gateway, балансировщик и Route 53 не создаются.
- Сохраняется существующий адрес `https://baboon-arriving-visually.ngrok-free.app`.
  Туннель переключается на AWS только после восстановления и проверки данных.

На Mac измерено около 685 MiB памяти шести рабочих контейнеров в текущем
состоянии. Это не измерение максимума: после переноса проверяются поиск,
очередь, memory pressure и отсутствие OOM. При нехватке памяти сначала
фиксируется причина, затем согласуется изменение размера.

## Хранилище, доступ и резервные копии

- Один зашифрованный AWS-managed KMS дисковый том `gp3`, 20 GiB,
  стандартные 3000 IOPS/125 MiB/s. Том сохраняется при удалении EC2.
- Включены termination protection и IMDSv2, metadata hop limit 1.
- CPU credits работают в режиме Standard: доплаты за Unlimited отсутствуют,
  но после исчерпания накопленных credits CPU ограничивается базовой скоростью.
- Базовые метрики CloudWatch и три alarm: CPU, CPU credits, status checks.
  Email/SNS-получатель пока не настроен; alarms видны в AWS Console.
- Роль EC2 имеет `AmazonSSMManagedInstanceCore`, чтение только `artifacts/*`
  и запись только `backups/*` в отдельном S3 bucket этого проекта.
  Контейнеры приложения не получают AWS credentials или доступ к metadata.
- Bucket приватный, с Block Public Access, Bucket owner enforced, versioning,
  SSE-S3 и запретом HTTP. Никаких публичных ссылок на данные.
- После проверенного восстановления включается ежедневная копия PostgreSQL
  вместе с файлами в S3, около 02:30 UTC. Это offline backup с коротким
  перерывом записи. Удаление прежних локальных резервных копий не выполняется.
- Планируется хранение ежедневных S3-копий 14 дней; lifecycle настраивается
  после успешной проверки восстановления. После успешной загрузки в S3 сервер
  удаляет только свои локальные `daily-*` копии старше 14 полных суток.
  Исходная копия переноса и прежние резервные копии Mac сохраняются отдельно.

## Порядок переноса и готовность

1. Полный quality gate действующего release против отдельной тестовой PostgreSQL.
2. Валидация `infra/aws/stack.json`, `bash -n` и EC2 dry run.
3. Подтверждение конкретной конфигурации перед запуском по AWS EC2 skill.
4. Создание stack, проверка EC2/SSM/bootstrap, загрузка точного image.
5. Обслуживание на Mac, завершение активных leases, остановка писателей,
   согласованный backup базы и файлов; исходные volumes и SQLite сохраняются.
6. Восстановление в новую AWS PostgreSQL и сверка хешей строк и файлов.
7. Проверка API, доступа, worker health, публичного HTTPS и сохранённой сессии.
8. Проверка S3 backup/restore, timer и восстановления служб после reboot.
9. Итоговый отчёт с фактическими результатами и конкретными ограничениями.

Перед проверкой восстановления трафик на AWS не переключается. После переноса
на Mac не запускаются параллельные писатели. Автоматический возврат на старую
БД после появления новых записей в AWS запрещён: сначала новая согласованная копия.

адреса тестовых серверов. Browser gate пока не зелёный; полный quality gate
с кодом 0 не заявляется. Изначальные порты 8011–8015 были заняты параллельной работой.

Ресурсы AWS не созданы, копирование рабочих данных и переключение трафика
не выполнялись. По исходному запросу переноса БД и backend выбран вариант

контраста не объявляется исправленным; красный UI-тест не скрывается и не
считается доказательством готовности новой UI-сборки или первой публикации проекта.
Перед созданием EC2 требуется отдельное подтверждение конкретной конфигурации
по процедуре загруженного AWS skill.
